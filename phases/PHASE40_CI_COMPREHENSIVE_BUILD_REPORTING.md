# Phase 40 — Comprehensive CI Build Report

**Date:** 2026-11-07  
**Status:** Workflow instrumentation added; GitHub Actions execution pending.  
**Scope:** CI reporting and diagnostic retention only. No application/runtime behavior changed.

## Objective

Every RAVEN23 Android CI run should produce a readable Markdown report that explains what actually ran, what passed, what failed, what was skipped, and which warnings/errors were emitted. The report must still be generated after an ordinary step failure so a failed run does not lose its diagnostic summary.

## Generated report and artifact

- Report filename: `RAVEN23-build-report.md`.
- Workspace copies: repository root and `build-artifacts/RAVEN23-build-report.md`.
- Uploaded artifact: `RAVEN23-build-report-and-diagnostics`.
- Retention: 30 days.
- The report is also appended to the GitHub Actions job summary.
- The artifact contains the report, captured command logs, environment snapshot, formatter patch/logs, and APK size report when those files were produced.

## Report contents

1. **Run identity and timeline:** UTC start and report-generation time, elapsed time, workflow run ID/attempt, run URL, repository, ref, commit SHA, trigger, actor and selected Release/Debug mode.
2. **Overall outcome:** job status plus failed, skipped and cancelled steps.
3. **Step-by-step status:** checkout; Java; Gradle; signing-key cache/setup; Flutter; Android SDK; dependency resolution; formatting; formatter patch capture; environment capture; Analyze; focused tests; complete test suite; Gradle wrapper; APK build; APK audit; and existing diagnostic artifact uploads.
4. **Toolchain snapshot:** runner OS/architecture, kernel, Flutter/Dart, Java, Gradle, Android SDK command-line tools, ADB and Python versions when available.
5. **Build configuration:** Flutter 3.35.7, Java 17, Gradle 8.7, Android API/build-tools/NDK pins, `prod` flavor, `lib/main.dart`, ARM64 target, Dart defines and expected package ID.
6. **Warnings/notices/errors:** per-log counts and bounded excerpts from captured command output; analyzer `info` findings are reported separately.
7. **Test diagnostics:** focused and full expanded logs, test summary markers, and the final 100 lines of the full suite log.
8. **APK diagnostics:** APK presence/size, ABI report, native-library payload, largest APK entries and package-name audit when the build reaches that stage.
9. **Diagnostic inventory:** list of generated raw logs and reports.

## Captured command output

The workflow tees stdout/stderr from the main commands to files under `build-artifacts/` while preserving each command's original exit code:

- `dependency-resolution.log`
- `dart-format.log`
- `flutter-analyze.log`
- `focused-flutter-tests.log`
- `full-flutter-test.log`
- `gradle-wrapper.log`
- `android-apk-build.log`
- `apk-audit.log`
- `ci-environment.txt` and run-context/timeline files

The complete raw logs are uploaded in `RAVEN23-build-report-and-diagnostics` (and selected test/APK/format logs remain in their existing dedicated artifacts). If a setup action fails before a shell command can run, the report records that action's step outcome and links to the GitHub Actions run; action-owned console details remain available in the run UI.

## Failure behavior

- Report generation and upload use `if: always()` so they run after an ordinary earlier step failure.
- A skipped build/test stage is explicitly labeled `skipped`; it is never represented as a pass.
- Command logs preserve non-zero exit codes instead of allowing `tee` to mask failures.
- The report does not relax `dart format`, `flutter analyze`, tests, ARM64 audit, or Release build gates.
- A workflow forcibly cancelled before the runner can execute the final `always()` steps may not be able to upload the report; in that case the run UI remains the authoritative source.

## Follow-up after first real report artifact — 2026-11-07

The first uploaded report/log pair (CI run `42328559177`) exposed a limitation: the previous report excerpt listed only a bounded number of generic error markers and did not identify all failed test cases. The report generator now parses each expanded reporter `[E]` status, deduplicates by test file/name, includes nearby assertion/exception/timeout details, and reports the total unique failures, affected files and explicit timeout count. Warning extraction now recognizes bracketed `[WARNING]` localization entries and deduplicates the displayed messages while retaining occurrence counts.

A synthetic replay using the actual uploaded log reproduced **34 unique failed tests across 18 files and 11 timeout failures** in the generated report. The replay also counted 6,157 localization warning occurrences (253 unique messages) instead of omitting bracketed `[WARNING]` entries. This replay validated report parsing only; it did not rerun tests or alter the CI run's original result.
