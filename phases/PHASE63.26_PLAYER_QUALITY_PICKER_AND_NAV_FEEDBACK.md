# PHASE63.26 — Player Quality Picker & Navigation Press Feedback (2026-11-16)

## Scope

This phase is based only on the RAVEN23 PHASE63.25 project. No Zangetsu, FlixQuest or OpenStream archive was inspected or modified.

## Navigation and press feedback

- The five primary bottom-dock destinations use the same existing `AppPressFeedback` behavior as the centre menu action: scale `0.985`, duration `100 ms`, `easeOutCubic`. The entire destination item (icon and caption) remains within one feedback boundary. A stable key (`mobile-nav-item-<tab-id>`) supports precise tests.
- The secondary dock retains the PHASE63.21 restored behavior: it collapses after a destination is selected; selecting Movies/Series/Anime still retains Home as the primary selection and restores the secondary destination selection when the dock is opened again. This phase does not keep the secondary dock open.
- The shared feedback component is the common implementation for buttons and action icons across the app (existing use in 81+ library files). It observes pointer events without taking ownership of callbacks, ink effects or haptics, cancels the press state when a pointer moves more than 10 px, and respects the platform Reduce Motion setting.
- Added the same feedback to the interactive hosted-ad image surface. It is disabled for display-only Android TV banners, and horizontal carousel swipes cancel the pressed state instead of retaining a scale response.
- Gesture-driven surfaces are intentionally not treated as buttons: the hero card parent has nested actions and must not sink while one is pressed; the Plus celebration overlay is a tap-to-dismiss canvas; wellness charts use tap/drag for data selection; player and Manga reader swipe regions remain gesture-controlled. Their actual buttons continue to use the shared feedback.
- Added widget coverage that presses a primary destination and the centre menu toggle, checks the same `0.985` scale and release to `1.0`, and verifies the whole destination column (icon plus label) shares the feedback wrapper. Playback action coverage also checks the quality row's press response and original tap callback.

## Cross-provider player quality picker

- Both the mobile quality sheet and Android TV quality menu consume the same `PlaybackQualityCatalog`. A resolution is now the primary title (`1080p`, `720p`, `480p`, `360p`, `140p`); server name and technical format (HLS/DASH/MP4 and request-header presence) are secondary details.
- The picker no longer represents a quality choice using a server label. Equal resolutions from different servers remain separate rows, with the server shown under the resolution. Expired links and embedded web pages are excluded from quality choices; embedded pages remain available through the server switcher because they do not expose a controllable rendition.
- Each catalog entry retains its owning provider bucket, the exact source key generated by `VideoUtils.videoSourceKeys`, original URL, format, headers, size token and adaptive metadata. Activation selects that exact keyed entry from the parallel source maps, rather than searching only by URL/provider. This prevents same-URL or same-provider links at different resolutions/mirrors from being treated as the same selected choice.
- The currently active row is selected/disabled by the exact provider bucket + source key + URL; other resolutions and mirrors stay tappable. Choosing a row invokes the existing guarded `PlaybackAction` flow, prepares the matching stream with its own format/header/token metadata, and closes the sheet after the switch succeeds. HLS/DASH adaptive entries retain Auto and each discovered rendition.
- Lower resolutions returned during a provider result remain in the catalogue and are normalized to labels such as `360p`, `270p`, `180p`, and `140p`. They are not used as additional mandatory scan targets.
- The background scanner's stopping contract is preserved: the standard completion target remains `{480, 720, 1080}`; reaching all three stops scheduling new providers, but already in-flight providers finish and their entire `videoLinks` list is kept. The target set controls scheduling only and is not a filter over returned resolutions. The provider scan remains scoped to the media identity (Movie, Series or Anime) and its VOD-capable providers.
